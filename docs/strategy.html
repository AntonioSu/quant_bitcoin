quant_bitcoin · 策略梳理

交易策略：四层结构与实际生效的规则

数据层 → 信号层 → 执行层 → 出场与止损。层与层之间靠不同的时钟驱动， 越往下越不依赖模型。所有参数取自代码而非文档， 凡与 README 或旧描述冲突之处，以本文为准。

一、数据层：22 路输入，三种刷新节奏

14 个外部采集器 + 8 个技术指标，全部汇入 market 单例这一条数据总线。

刷新节奏

三条刷新循环各跑各的，互不等待：

循环周期对齐LLM 开销
市场数据 + 指标重算300 秒固定间隔无

新闻情绪分析2 小时双小时对齐每轮 1 次调用
 另有两条不属于数据层的时钟：交易循环每 5 分钟跑一次（每次都问一次交易 AI）、前端 WebSocket 推送 5 秒。
信号必然比行情旧 研判每小时一次、基于 4H K 线收盘价；而交易循环每 5 分钟取一次实时标记价。 所以开仓瞬间用的方向判断，最坏情况已经是 55 分钟前的结论 —— 但止损价位是用当前价算的。这个不对称是设计取舍，不是缺陷。

二、信号层：多空并行论证，再交给审查与拍板

DecisionCommittee 里多头和空头互不看见对方输出，两边都完成后才进风险审查员，最后才是决策经理。各自有独立 system prompt 和知识库切片。

多头研究员 空头研究员
风险审查员 → 决策经理

多头和空头拿同一份快照，只构造本方论证，不给结论，也不读对方的稿。 代码里仍是先调多头再调空头，但两边输入相同、互不依赖，逻辑上是并行。 风险审查员看完双方论证后产出 entry_ok，并且拥有否决权 —— 决策经理不能把它翻回来。

多头和空头快照内容

两边 user prompt 里的「当前 BTC 市场快照」是同一份 JSON，由 MarketAnalyzer._build_snapshot() 从 market 压出来。 某路还没刷到时，对应键直接不出现。不含原始新闻、不含持仓、也不含对方的论证。

风险审查员

risk_level entry_ok position_size_hint blockers
low / medium true 25% ~ 50% 空
high true 25% 写明具体担忧
extreme false 0% 必须有阻断项
输出字段就是这四列。schema 还会再钳一次：extreme 或仓位 0% → entry_ok=false。 另外两条硬阻断不走这张表：HIGH_VOL_EXTREME 且爆仓异常、多空双方证据都极弱。
提示词里明确写了「entry_ok 默认倾向应该是 true」「零交易 ≠ 零风险」， 并列出三条「绝对不应该阻断」的情况（双方置信度相近、存在矛盾信号、缩量）—— 审查员的职责被定义为管控风险，不是消灭风险。

决策经理

user prompt 三块：市场快照、委员会三方结论、动态上下文（上次研判 / 备忘录）。 快照就是数据层那 22 路输入的当前值 —— 新闻情绪、资金费率、ETF 流向、技术指标全在里面， 四个角色拿到的是同一份。持仓由调度器每 5 分钟写入 market.position_context，也嵌在快照里。 bias 是市场方向，不因已有仓位而翻转； action 必须和当前是否有仓一致：空仓只能加多／加空／等待入场， 有仓只能持仓观望／减仓／离场，不得在已持仓时再输出加多／加空。

输入 · 下表只展开快照里的持仓这一块，其余输入见数据层

字段取值含义
is_active true / false 当前有没有合约仓。空仓时这一项为 false，下面各字段都不出现
direction LONG / SHORT 持仓方向。与 bias 同向则继续拿，反向才考虑减仓／离场
size_btc BTC 数量 当前仓位大小，用来判断是轻仓还是已满
leverage 整数倍 本仓杠杆。高杠杆时离强平更近，反向信号要更敏感
entry_price USD 入场均价。和现价比才知道浮盈还是浮亏
current_price USD 当前标记价
liquidation_price USD 强平价。距现价过近时不得建议继续扛
holding_duration 如 6h 20m 已持多久。刚开仓的反向信号要更谨慎，拿了很久才更可能是结构变了
委员会三方（bull.thesis / evidence、bear.thesis / evidence、 risk.entry_ok / risk_level / position_size_hint / blockers）始终传入，与有没有仓无关。

输出

字段取值含义

confidence / confidence_level 0–100；WEAK…VERY_STRONG 方向确信程度。决定空仓时仓位／杠杆上限，也决定有仓时该观望还是离场
trend_regime UP_TREND / DOWN_TREND / RANGE / UNCLEAR 趋势状态
volatility_regime LOW_VOL_COMPRESSION / NORMAL_VOL / BREAKOUT_EXPANSION / HIGH_VOL_EXTREME 波动状态。极端波动时仓位和杠杆都要压
entry_ok true / false 只约束新开仓。有仓时 false 不是平仓理由

position_size_hint 0% / 25% / 50% / 75% / 100% 空仓且允许开仓时的保证金占权益比例；有仓或不可开仓时必须为 0%
leverage_hint 1 / 2 / 3 / 5 / 10 / 20 空仓开仓时的杠杆上限。有仓时不影响已有杠杆

key_drivers 3–5 条 方向依据。每条含 factor / side / weight

有仓 · 同向 = 持仓方向 持仓观望 论点仍在，继续拿。论点削弱则改为减仓
有仓 · 反向 ≠ 持仓方向 离场 结构反了，先平掉本仓。不够确信则减仓
有仓 · 中性 NEUTRAL 持仓观望 方向不清，不主动加也不主动砍
有仓时禁止输出加多／加空。position_size_hint 一律 0%。

提示词里有一条强制的维度优先级，用来压制振荡指标的话语权：

  • M2／稳定币供应 > ETF／净流／均线结构 > CVD／订单流 > RSI／MACD
  • RSI 或 MACD 出现在 key_drivers 时权重不得为 high，单独出现必须为 low
  • 不得因 RSI／MACD 与流动性冲突而翻转 bias，冲突时以流动性为准
  • 计维时 RSI + MACD 合计最多算 1 个同向维度

CommitteeDecision：经理说了不算

经理输出的只是一段 JSON 文本，会漏字段、也会自相矛盾。它先被 _merge_risk_into_manager_payload() 落实审查员的否决，再交给 schemas.py 里的 CommitteeDecision 校验 —— 上面那张输出表就是它的字段定义。校验后的结果才写进 market.ai_analysis， 信号聚合器与执行层只读这一份。所以生效的不是经理写的值，是被改写之后的值。

会被改写的几种情况

触发条件被改写成
confidence < 35 entry_ok=false、仓位 0%、加多／加空 改为等待入场
entry_ok=true 但仓位是 0% 按置信度补全为 25% / 50% / 75% / 100%，避免经理漏填就被 0% 误杀
bias=NEUTRAL entry_ok=false、仓位 0%、加多／加空 改为持仓观望
entry_ok=true 但 action 不是开仓动作 按 bias 反推出加多／加空（经理常省略 action）
置信度偏低 / HIGH_VOL_EXTREME 钳制 leverage_hint，见开仓门槛一节
其余都是同类的一致性收敛：越界值夹回合法区间，entry_ok 与仓位互相约束， 不许出现「不让开仓却写着加多」这种组合。

每次挡下入场都会在 entry_gate 上留一个记号，写明是谁挡的：风险审查员否决、 经理自己不开、还是上面这些规则改的。它不参与下单判断，只用于事后统计哪道闸真正在起作用。

经理是唯一没有兜底的角色 多头、空头、风险审查员各自失败都有保守兜底（审查员兜底直接阻断入场），流程照常往下走。 但经理的 JSON 解析或校验一旦失败，就抛 DecisionCommitteeError， MarketAnalyzer 接住后整轮作废，写入 bias=NEUTRAL、 confidence=0、entry_gate=COMMITTEE_FAILED —— 这一小时既不开新仓，也不会因此平掉已有仓，要等下一个整点重跑。

三、执行层：开仓与下单

交易 AI 只说「开 / 平 / 减 / 观望」。真正下单前，代码再拦一遍：够不够门槛、刚平过能不能马上再开、减仓会不会减得太碎。

开仓门槛按置信度分档

等级置信度维度共振仓位杠杆上限
VERY_STRONG≥ 80≥5 维同向100%10x *
STRONG≥ 654 维同向75%5x
MODERATE≥ 503 维同向50%5x
CAUTIOUS≥ 352 维同向不开仓3x
WEAK< 35≤1 维同向不开仓2x
 「维度共振」是提示词层面的启发式，不是代码计算量；置信度阈值与仓位映射则是 schemas.py 的代码约束。杠杆只能取 1／2／3／5／10／20，其余值就近吸附。
* VERY_STRONG 的 10x 上限没有代码兜底 schemas.py 的杠杆钳制是一条 if/elif 链：置信度 <35 压到 2x、<50 压到 3x、 <65 压到 5x、<80 压到 5x —— 而置信度 ≥80 时一条分支都不命中，不做任何钳制。 10x 这个上限只写在提示词里，模型若输出 20x 会被原样放过（仅 HIGH_VOL_EXTREME 波动状态会压到 3x）。 也就是说，唯一允许最高杠杆的那一档，恰好是唯一没有代码保护的一档。

仓位算法

下单前的硬规则

交易 AI 说了要开、要减，代码还会拦一次。拦的是下单，不管持仓中该不该平（那是下一层的事）。持仓中它提议的 stop_r 另有硬钳，见兜底与硬钳。

  • 开仓门槛：允许入场 + 方向对上 + 等级至少中等，否则不开
  • 追高不让开：顺方向落在近 48 小时区间的 60–100% 拒绝；真正突破（超过 100%）才放行
  • 刚平过不能马上再开：同方向 15 分钟内不重开，同一份研判也不重开（防止止损刚打掉又原样开回去）
  • 减仓别减太碎：一次减 10%–90%；同一仓最多减 2 次，第 3 次或剩不到 20% 就全平

四、出场与止损：仓开起来之后怎么管

管的是仓位开起来之后：要不要减、要不要平、止损往哪推。不管方向判断，也不管能不能下单。

主要功能

开仓那一刻先定好「亏多少算一笔」：交易 AI 只给一个 ATR 倍数（1.0～3.0，越界会被夹回去）， 代码换成真实止损价和 1R 金额。不让它直接写绝对价格，避免现价延迟或拍脑袋把止损写到贴近强平。

之后每 5 分钟再问一次。分工是：AI 管要不要走，代码管止损几何。 AI 看着当前信号和本仓的盈亏位置，输出 持仓观望 / 减仓 / 平仓，以及可选的 stop_r（把硬止损推到 入场价 + stop_r × R）。 论点被推翻才离场；止损能不能往前推，要过 _apply_ai_stop() 的硬钳。

代码不会自动保本、不会自动移动止损、不会自动部分止盈。 AI 两次决策之间，只靠硬止损和强平价把仓砍掉。

出场策略

情况动作
信号同向或中性，走势正常持仓观望（默认，绝大多数时候都是这个）
论点被削弱，或浮盈较大想先落袋一部分减仓
方向反转且确信，或突破明确失败平仓
峰值 ≥ 1.5R，想锁住利润或抬到保本给 stop_r，止损只许收紧不许放宽；离现价至少 0.6R
峰值 < 1.5R，却要求 stop_r ≥ 0代码忽略，止损不动
 不因小幅浮盈全平，也不把止损提前收到保本来变相全平。 entry_ok=false 只拦新开仓，不是平仓理由。

兜底与硬钳

规则谁执行作用
硬止损 AI 定价位，代码 / 交易所执行 开仓时定下 −1R；之后 AI 只能往有利方向推。价格碰到即全平。实盘挂在交易所，不等 5 分钟轮询
止损几何硬钳 代码拦 AI 的 stop_r 峰值不到 1.5R 拒绝保本/锁利；新止损离现价不足 0.6R 拒绝贴价。亏损侧收紧仍允许
强平价 交易所 触及即全平，关不掉。算出的止损若穿透强平价，会被拉回强平价内侧

_apply_ai_stop() 按这个顺序拦，任一命中就忽略这轮 stop_r，止损不动：

参数默认含义
min_breakeven_peak_r 1.5 峰值低于此值时拒绝 stop_r ≥ 0。0.5R 是呼吸，不是保本位
min_stop_distance_r 0.6 新止损离现价至少这么多 R，否则视为贴价
两值写在 RiskConfig，三档相同，提示词无权覆盖。 已经推进过的止损不会退回去（棘轮仍在）。
为什么要钳，而不是把止损交回代码自动跑 提示词曾经写「浮盈过 0.5R 就通常保本」，示例 JSON 还默认带 stop_r=0。模型每 5 分钟被问一次，最省事的风控动作就是提前保本； 止损只能收不能放，价格一呼吸就被扫掉，委员会就算还在同向也回不去。 现在改成：离场判断仍归 AI，保本门槛和呼吸空间归代码。

五、三档预设的真相：其实只有一套策略

保守／标准／激进三档在运行时几乎没有差异 —— 大部分参数已经没有任何代码在读。

全仓检索后，运行时真正被读取的配置只有这些：

参数保守 / 标准 / 激进实际作用
atr_multiplier2.0 / 1.5 / 1.2 仅当 AI 不给 stop_atr_mult 时的兜底默认值
long.leverage10 仅实盘交易所侧兜底杠杆，每笔实际杠杆由 AI 覆盖
RiskConfig 追高拦截三档完全相同 开仓前的追高硬规则，AI 无权干预
min_breakeven_peak_r / min_stop_distance_r 1.5 / 0.6 推进止损的硬钳，三档相同，AI 无权覆盖
结论：并行跑三档，得不到参数敏感性对比 三档唯一的实质差异 atr_multiplier，只在 AI 不指定止损倍数时才生效 —— 而现在提示词要求 AI 必须给出，所以连这一个差异也基本不触发。 持仓中的保本 / 移动止损仍由 AI 提议，但 1.5R 之前的保本和贴价止损会被代码拒绝，与档位无关。 三档跑出来的行为几乎完全一样，本质上是同一套策略的三份随机复现。 要真做档位对比，得先让档位去影响 AI 拿到的约束（例如按档给不同的参数建议区间）， 而不是改一组它随手就会覆盖掉的默认值。
